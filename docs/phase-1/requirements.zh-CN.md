# zhupi-mcp Phase 1 需求 —— 只读工具

> 三段走（requirements → design → tasks）的第一段。这份只回答**「什么才算对」**，不回答「怎么建」——技术选型、模块切分、数据流全部留给 design。
> 上层背景见 [SPEC](https://github.com/charliezong18/zhupi-mcp/blob/main/SPEC.zh-CN.md)，阶段判据见 [MILESTONES](https://github.com/charliezong18/zhupi-mcp/blob/main/MILESTONES.zh-CN.md)。

## 这一阶段要解决的痛

**「读批注」现在每次都要烧一大块 context。** 模型得打一串 `gh api`、自己解析 threads 和 inline position、自己推「哪条我还没回」。这个成本每次呈折循环都付一遍，是 SPEC §1 里排第一的理由。

Phase 1 只做**只读**——出错代价最低，收益立刻兑现。

---

## R1 · 服务能挂上

**要满足**：Claude Code 按本地绝对路径把 server 挂上之后，会话里能看到并调用它的工具。

**怎么算过**

- 配置写好、会话重启后，工具列表里出现 `list_folders` 与 `read_comments`
- 各调用一次，返回的是数据而不是错误
- 全过程不产生任何全局状态（不 `npm link`、不写 `/usr/local`）

---

## R2 · 列折 —— 「有哪些折在等我」

**要满足**：一次调用就能知道有哪些折开着、以及**哪些已经批了但我还没回**。

**怎么算过**

- `state=open`（默认）返回全部未合的折，每条带：折号、标题、分支名、**未回批注数**
- `state=merged` 返回已钦此的折
- 未回数与人工数出来的数字一致（见 R4）
- 奏折仓里一条折都没有时，返回空列表而不是报错

---

## R3 · 读批注 —— 一次调用拿到结构化结果

**要满足**：模型拿到手就能用，不需要再解析、再推理。

**怎么算过**

- 给折号 → 返回那一折；不给 → 扫全部 open 折
- 每条 inline 批注带：批注 id、文件路径、行号、**被划中的引文**、批注正文、串归属（回复的是哪条）、**是否已回**
- 会话区留言（总批）同样带正文、作者、**是否已回**
- 返回里不出现「原始 JSON 让模型自己挑」的部分
- **拿本折之前那折（#18）当真样本核对**：它有 1 条总批且我方已回话 → 未回数应为 0

---

## R4 · 「未回」的判定要和人一致

**要满足**：服务端算出来的「未回」，跟你心里的「你还没答我」是同一件事。

**怎么算过**

- 一条 inline 批注下面没有我方 reply → 未回
- 会话区里你的留言之后没有我方留言 → 未回（**你不划行、整条列意见也算批注**，这是现有惯例）
- 我方自己发的批注不计入未回
- 判定由服务端完成，不是把原始列表丢回给模型自己推

---

## R5 · 不新增要维护的凭据

**要满足**：不引入第二份会过期、要人记得续的密钥。

**怎么算过**

- 用机器上已有的 GitHub 认证，不要求单独配 PAT
- 认证失效时报出的话，能让人直接知道该去做什么

---

## R6 · 错误面向模型可执行

**要满足**：出错时返回的是「你该怎么修」，不是 stack trace。

**怎么算过**

- 认证拿不到、仓不存在、折号不存在、网络失败——四种各有一句人和模型都读得懂的话
- 报错里不泄露 token

---

## R7 · 绝对只读

**要满足**：这一阶段不可能改动任何远端状态。

**怎么算过**

- 全部代码路径不含创建、修改、删除类的远端调用
- 即使被误调，奏折仓也不会有任何变化

---

## 非目标（这一阶段明确不做）

呈折、体例检查、存量巡检、回话、钦此。**跨 harness 也不验**——agy 已出局、Codex 不急，这条 2026-07-29 已从 Phase 1 判据里删掉。
